# 客户端接入

[English](CLIENTS.en.md) · [返回首页](../README.md)

先启动模型，等待“服务已就绪”，再打开“客户端接入”。页面优先显示当前运行模型的实际端口、ID 和上下文；仅在左侧选择另一模型，不会改变已运行服务的连接信息。

下面以端口 `8081` 为例。API Key 的 `local` 只是非空占位值，当前启动的本地服务未配置密钥验证。

| 客户端 | 地址 | 协议 |
| --- | --- | --- |
| WorkBuddy | `http://127.0.0.1:8081/v1/chat/completions` | 自定义协议，完整路径 |
| Cherry Studio | `http://127.0.0.1:8081/v1` | OpenAI / Chat Completions |
| DeepSeek Harness | `http://127.0.0.1:8081/v1` | 自定义模型 API / OpenAI Chat Completions |

## WorkBuddy

1. 选择 WorkBuddy，核对生成配置中的 URL、模型 ID 和预算。
2. 点击“写入 WorkBuddy”，合并到 `%USERPROFILE%\.workbuddy\models.json`。现有配置先备份，再写入。
3. 在 WorkBuddy 重新选择生成的本地模型；必要时重新打开客户端或新建任务。
4. 手动配置时开启“自定义协议”，使用完整 `/v1/chat/completions` 地址。

写入保留其他模型和目标条目的未知字段；遇到损坏 JSON 或同 ID 的非本地配置会拒绝覆盖。复制/导出的 JSON 只是单模型片段，不应用它直接覆盖整个配置列表。

备份区可以刷新列表、打开目录和恢复选中的备份。恢复会先备份当前配置，再写入所选备份的原始字节；损坏或不属于该配置的备份会拒绝恢复。

## Cherry Studio

1. 点击“导入 Cherry Studio”，在 Cherry 自己的确认窗口中接受服务商导入。
2. 在该服务商中获取/添加模型，使用启动器显示的准确模型 ID。
3. 在聊天窗口选择此服务商与模型。

导入链接只包含服务商配置，不包含模型列表。切换同一端口上的模型后，需要更新并重新选择模型。原生链接依赖 Cherry Studio 已注册 `cherrystudio` 协议；不能将服务商类型选为 Ollama 或 Responses。

## DeepSeek Harness

1. 点击“复制 Harness 填写信息”。
2. 在 Harness 原生模型设置中添加自定义模型 API，使用显示的 Provider ID、基础 URL、OpenAI Chat Completions 和 `local`。
3. 获取并添加模型，按页面预算填写上下文与最大输出，然后选择模型新建会话。

也可以导出 YAML 片段，按当前 Harness 的配置结构手动合并到 `llm-pi-ai`。启动器不会自动改写 YAML；具体配置位置以 Harness 自身界面为准。菜单和协议字段以实际客户端版本为准。

## 测试与常见问题

- “检查连接”只检查 `/health` 与 `/v1/models`。
- 基础、流式、工具测试会实际生成，最长三分钟，可以取消。工具只回显 `ping`，没有外部执行器。
- **404**：核对端口、路径和协议，尤其区分 WorkBuddy 完整地址与其余客户端基础地址；不要重复添加 `/v1`。
- **模型不可用**：核对 `/v1/models` 返回的模型 ID，切换模型后在客户端重新选择，必要时新建任务。
- **连接被拒绝**：确认服务已就绪，启动器没有真正退出，地址指向服务所在电脑。
- **只有思考没有正文**：检查输出预算，调整思考设置后重启；模板支持不等同于实际行为已验证。

这三项自检验证本地服务接口，不验证第三方客户端的整个 Agent 工作流。工具、视觉、长上下文和复杂任务需分别实测。
